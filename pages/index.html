What makes this firmware different

  • Update a node without leaving home One command over the mesh. The node fetches the firmware, verifies it, installs it, and comes back. About a minute.
  • A bad update cannot strand a node New firmware runs on probation. If the radio never comes up, the node reverts to the previous image and reboots itself.
  • Clocks that do not lie Nodes set their clock from NTP whenever they join WiFi, so "last heard from" means something after a restart.
  • Settings arrive already correct Radio settings, advert timings and the region map are applied from a file your local community maintains. No CLI session.

MeshCore: stock vs enhanced

Stock MeshCore is great, but updates can be a pain. Its start ota turns the node into an access point and waits for a person standing nearby to upload a file. These builds add a second path over an existing WiFi or cell hotspot, with remote power control for the hotspot itself, driven by ordinary CLI commands that travel over LoRa like everything else in the mesh.

Situation Stock MeshCore MeshCore Enhanced
Updating a remote node Take a trip Send a command over the mesh
A bad firmware image Node halts and stays down Recovers itself and reboots
Radio settings Do your research Applies regional community settings
Clock after a reboot Best guess timestamp Uses NTP set from atomic clocks

Advanced configuration

The configurator exposes every internal setting, names a repeater, sets its region transport scopes, and pushes the lot over USB. Boards running our enhanced firmware expose more settings than stock does. The tool assumes familiarity with how the mesh is configured (a wrong value can quietly take a repeater off the air). This is not the tool for a first-time user, but for someone who knows MeshCore's internals and likes turning knobs.
